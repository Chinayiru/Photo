# PhotoBridge 远程照片

> 用手机看**你自己电脑里**的照片。照片不上云、不进第三方服务器 ——
> 手机和电脑在同一个 Wi-Fi 下直连，**一个字节都不出局域网**。

---

## 这是什么

一个自建的私人照片库，解决一个具体问题：

**手机在客厅，想翻一眼电脑里存的那几千张照片。**

市面上的相册 App 都要先把照片上传到别人的服务器。这个项目不走这条路：

| | 网盘 / 相册 App | **PhotoBridge** |
|---|---|---|
| 照片存在哪 | 厂商的服务器 | **你自己的电脑** |
| 谁能看到 | 厂商 + 你 | **只有你** |
| 容量上限 | 按套餐收费 | **硬盘多大就多大** |
| 隐私 | 依赖厂商承诺 | **没有任何服务器参与** |
| 费用 | ¥10–30/月 | **¥0** |
| 断网能用吗 | 不能 | **能，本来就不需要外网** |

## 它怎么工作（一期）

```
     手机（同一个 Wi-Fi）              你的电脑（Windows）
          │                                  │
          │   HTTP + 配对令牌                 │
          ▼                                  ▼
   ┌──────────────┐                  ┌──────────────────┐
   │  浏览器网页   │ ───────────────▶ │  PhotoBridge.exe │
   │  （无需安装）  │ ◀─────────────── │  127.0.0.1:8787  │
   └──────────────┘   缩略图 / 原图    └────────┬─────────┘
                                               │ 只读+受控写入
                                          ┌────▼─────┐
                                          │ E:\相册   │
                                          └──────────┘
```

**三个关键点：**

1. **不需要公网 IP、不需要端口映射、不需要域名、不需要买服务器** —— 只要手机和电脑连同一个路由器
2. **照片永远不动地方** —— 程序读你已有的文件夹，不搬家、不导入、不改名（除非你上传新照片）
3. **写权限被三条硬约束锁住** —— 见下面的[安全承诺](#安全承诺)

> **二期（未实现）**：电脑主动外连云服务器中继，让手机在外面（4G/5G）也能访问。
> 传输层已做成可插拔适配器，`shared/protocol.py` 的隧道帧协议也已写好，
> 二期接入时**业务代码零改动**。见 [docs/09](docs/09-开发计划与任务分解.md)。

## 能做什么（一期）

| 功能 | 说明 |
|---|---|
| 📷 **看照片** | 时间线缩略图、全屏查看、缩放、EXIF 详情（机型/光圈/快门/ISO/GPS） |
| ⬆️ **传照片** | 手机相册批量上传进电脑，分片 + 断点续传 + 秒传去重 + 按拍摄日期自动归档 |
| ⬇️ **下载原图** | 单张原图下载回手机（支持 Range，可断点续传） |
| 🔍 **搜索** | 按文件名、**目录名**、相机型号、日期范围、有无 GPS |
| 🗂 **浏览目录** | 按原目录结构浏览（递归计数 + 封面图） |
| 🗑 **删除** | 进 Windows 回收站，可还原；**代码里不存在永久删除路径** |
| 🔗 **配对鉴权** | 电脑显示 6 位配对码，手机输入绑定，可随时撤销设备 |
| 📱 **添加到主屏幕** | 无需下载安装包，浏览器"添加到主屏幕"即可 |

**一期明确不做**：视频（`.mov`/`.mp4` 不索引）、ffmpeg 转码、RAW、人脸识别、公网分享链接、多用户、E2E 加密。

## 快速开始

### 方式一：直接用 exe（推荐给最终用户）

从 [Releases](https://github.com/Chinayiru/Photo/releases) 下载 `PhotoBridge.zip`，
解压到任意目录（**不要在 Program Files 或 U 盘里**，程序要在自己旁边写数据），双击 `PhotoBridge.exe`。

- 右下角出现托盘图标，菜单里点**「显示配对二维码」**
- 手机浏览器扫码（或手输 6 位配对码）即可
- 首次运行会自动探测照片库；探测不到就打开菜单里的「打开设置」手动选

程序的数据（索引库、缩略图缓存、日志）就在 exe 旁边的 `data/` 目录里。
**整个文件夹就是全部状态**，备份或迁移直接复制它即可。

### 方式二：从源码跑（开发用）

#### 你需要准备

1. 一台 Windows 电脑，装 **Python 3.11+**（[下载](https://www.python.org/downloads/)）
2. 你的照片文件夹（首次运行会自动探测常见位置，探测不到可在 `data/config.json` 改）
3. 手机和电脑连**同一个 Wi-Fi**

#### 跑起来

```bash
git clone https://github.com/Chinayiru/Photo.git
cd Photo

python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# ★ 必须显式传 --host 0.0.0.0，否则只有本机能访问
.venv/Scripts/python.exe -m backend.app.main --host 0.0.0.0
```

启动后终端会打印局域网地址（形如 `http://192.0.2.10:8787`）。手机浏览器打开它：

1. 电脑上运行 `POST /panel/pair-code` 或点托盘菜单，拿到 **6 位配对码**
2. 手机上输入配对码 → 完成绑定
3. 之后手机直接打开这个地址就能看照片

> 首次启动会自动索引照片库。4915 张约 18 秒，索引期间手机就能连上（扫描在后台跑）。

### 常用参数

```bash
python -m backend.app.main --host 0.0.0.0 --port 8787   # 指定监听地址与端口
python -m backend.app.main --rescan                     # 启动时强制重扫
python -m backend.app.main --config D:\my.json          # 用别的配置文件（数据目录也跟着走）
python -m backend.app.main --no-tray                    # 前台运行，不要托盘图标
python -m backend.app.main --version
```

### 自己打包

```bash
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m PyInstaller packaging/photobridge.spec --noconfirm
# 产物：dist/PhotoBridge/PhotoBridge.exe（约 75 MB，含 _internal/）
.venv/Scripts/python.exe scripts/verify_exe.py          # 在真产物上验一遍
```

用 **onedir** 而不是 onefile：onefile 每次启动都要把整包解压到 `%TEMP%\_MEIxxxxxx`，
启动慢 1~3 秒、杀毒软件反复扫描甚至拦截、强杀后残留几十 MB 垃圾。

## 技术栈

| 层 | 技术 | 为什么 |
|---|---|---|
| 电脑端服务 | Python 3.12 + **Starlette** + uvicorn | 业务逻辑全在 `handlers/` 里只吃 `Ctx` 返回 `Reply`，用不上 FastAPI 的依赖注入；二期隧道通路上根本没有 `Request` 对象 |
| 数据库 | SQLite（WAL） | 单用户场景零运维；WAL 下读不阻塞写，索引器在写的同时手机能翻页 |
| 图片处理 | Pillow + pillow-heif | **必须支持 iPhone 的 HEIC**，否则安卓看不了 |
| 手机端 | Vue 3 + Vite + TypeScript | 无 UI 框架、无 vue-router、无 Pinia —— 自写 reactive store 省约 5 KB gzip |
| 删除 | Send2Trash | 进系统回收站，用户在资源管理器里右键就能还原 |
| 打包 | PyInstaller (onedir) | 用户机器上不需要装 Python |

**为什么不用**：FastAPI（依赖注入在这里是负担）、PostgreSQL（单用户不需要）、React（体积）、ffmpeg（一期没有视频）、`ImageMagick`/`sharp`（Pillow 够用且是纯 Python 依赖）。

## 已知限制（诚实说明）

| 限制 | 说明 | 缓解 |
|---|---|---|
| **电脑必须开机** | 关机/睡眠时手机连不上 | 这是"私有云盘"的本质，不是 bug |
| **只能在家用** | 一期只有局域网直连，出了家门访问不了 | 二期上云端中继 |
| **Wi-Fi 不是安全上下文** | `http://192.168.x.x` 下浏览器禁用 Service Worker、完整 PWA 安装、`navigator.wakeLock` | 一期靠"配对令牌 + 局域网"兜底；二期有 HTTPS 域名后这三条自动可用（相机直拍 `<input capture>` 不受影响） |
| **家庭宽带上行小** | 通常 30–50 Mbps，批量下载原图受限 | 局域网内网速通常 300–1000 Mbps，基本不是瓶颈 |
| **一期没有视频** | 12 个 `.mov` + 3 个 `.mp4` 不索引 | 二期实现 |
| **归档会改文件名** | 上传的照片按拍摄时间重命名为 `20240512_183000.jpg`（避免 iPhone 的 `IMG_1234` 大量重名） | 原文件名保留在上传记录与审计日志；搜索同时匹配目录名，你记得的"敦煌那张"仍然搜得到 |
| **托盘/自启只做 Windows** | `HKCU\...\Run` 注册表键是 Windows 专有 | 照片库与 HTTP 服务本身跨平台，Linux 上可用 `--no-tray` 前台运行 |

## 关于你的照片库

首次运行会**自动探测**常见位置（`D:\Photos`、`D:\Photos` 等两层以内），
探测不到就留空让用户手动选 —— 程序**不会**去猜一个可能不存在的路径。

开发机实测的照片库包含 **4952 个文件**：

- 图片 4915 张：4789 `.jpg`、68 `.png`、49 `.jpeg`、7 `.webp`、2 `.gif`
- **跳过 37 个**：12 `.mov` + 3 `.mp4`（视频，二期做）+ **22 `.jpg-lx2`**（小米相册回收站残留，不是真实图片）
- 3 个子目录：`全部备份\`、`相册1\`、`青甘环线\`

`.jpg-lx2` 被跳过是**预期行为，不是 bug**。`全部备份\` 目录名暗示可能有重复照片，上传时用 sha256 去重。

## 安全承诺

这个项目对你的照片有写权限（因为要支持上传），因此有四条不可违反的硬约束：

1. **所有文件访问必须经过路径沙箱** —— 拒绝 `../` 穿越、绝对路径、UNC、NTFS 数据流、Windows 保留名、符号链接与 **junction**（`os.path.islink()` 对 junction 返回 `False`，这是 Windows 上最容易被忽略的越界方式）
2. **上传只新增，绝不覆盖** —— 用 `O_CREAT|O_EXCL` 原子占位而不是"先检查再写"（后者两线程同时通过检查会互相覆盖）；同名自动加 `_1`/`_2`
3. **删除只进回收站** —— 代码里**不存在**永久删除路径，删除/移动/改名全部写审计日志
4. **云端零存储**（二期）—— 云上只有设备列表与配对码，没有一张照片；VPS 挂了换一台 10 分钟重建，照片一张不丢

另外：**所有错误响应都经过脱敏**，绝不返回绝对路径、异常堆栈、SQL 片段或库内文件名 —— 因为手机可能截屏给别人看。有 11 条测试专门断言这一点。

详见 [docs/06-安全设计文档.md](docs/06-安全设计文档.md)。

## 开发

```bash
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt

# 单元 + 集成测试（约 30 秒，530 条）
.venv/Scripts/python.exe -m pytest backend/tests/

# 路径沙箱专项（56 条）
.venv/Scripts/python.exe scripts/check_sandbox.py

# 真实库端到端冒烟（真起 uvicorn、真发请求、真扫 4915 张，35 项）
.venv/Scripts/python.exe scripts/smoke_real.py

# 打包产物验证（端口占用提示 + 数据目录位置）
.venv/Scripts/python.exe scripts/verify_exe.py

# 前端类型检查 + 构建
cd frontend && npm run build
```

### 维护脚本

| 脚本 | 用途 |
|---|---|
| `scripts/repair_index.py` | 按**磁盘事实**修复 `missing` 标记（默认演练，`--apply` 才写库；写前自动备份） |
| `scripts/clean_dev_artifacts.py` | 清掉开发期在真实数据里留下的测试设备/配对码/临时分片（**不动 media 表**） |
| `scripts/check_docs.py` | 文档一致性（相对链接断链、未完成标记、需求编号覆盖） |
| `scripts/check_frontend_api.py` | 后端路由 vs 前端引用对照 |

`scripts/smoke_real.py` 是单测的假数据掩盖不了的一层 —— 它发现过两个只有真实照片才会暴露的 bug（73 个文件写着非法的 `Orientation=0` 会让整批 500 行写入失败；搜索命中不了目录名）。
