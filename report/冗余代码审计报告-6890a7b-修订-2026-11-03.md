## 五、结论

**不给单一"冗余总量/占比"**：四类计量单位不同（归一化行 / 函数跨度 / 手工估算 / 诊断条数），相加没有意义。要报数就分三类报，并说明口径。

证据强度排序（复核第七节的处理顺序）：

1. **证据最清楚、且已完成**：`config.py` 重复属性与常量（R1-21）、前端字节格式化（R1-16）、游标分页管道（R1-14）、Range/416 响应构造（R2）。前两项是纯删除 → 零行为变化；后两项是抽取共用函数 → 行为保持一致（唯一有意改动：转码 416 补 `Accept-Ranges`）。
2. **已完成（批次 2）**：scripts 5 份 `real_fingerprint`（R1-01）—— 输出契约统一为 `rows=… missing=… maxid=…`，抽成 `scripts/_e2e_common.real_db_fingerprint()`；前端两个视图的 PhotoGrid props（R1-02）—— 核对完差异后判定**不抽**（理由见上表）。
3. **需要人决策**：27 项 R3 候选（逐项做限定名引用 + API 兼容判断，**不能批量删**）、`shared/protocol.py` 的 `Transport` 预留接口、`pair_codes` 两侧策略统一。

**明确不建议清理**：`watcher.py` 的 `on_modified/on_created/on_deleted/on_moved`（框架回调）、`protocol.recv_bytes`（协议成员）、`transports/base.py` 的三个再导出（删了传输包装配会 `ImportError`）、两端同名不同义的 `devices`/`schema_version`（各自管理）、测试里同名 fixture 的直接合并。
