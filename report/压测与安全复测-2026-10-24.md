# 压测与安全复测（2026-10-24）

对象：家里电脑上的 PhotoBridge（`127.0.0.1:8799`），以及手机经组网（Tailscale
`100.103.255.39`）进来的同一条链路。
目的：回答两个问题 —— **能扛多少**、**能被怎么打**。

## 一、环境与方法

- 服务：`D:\Photos`，`pythonw scripts/run_tray.py`，监听 `0.0.0.0:8799`。
- 探针凭据：`build/_probe_token.txt`（用库内配对码自签的 `client_token`，不是账号口令）。
- 压测脚本：`build/_stress_sec.py`、`_stress_sec2.py` … `_stress_sec6.py`（一次性，未入库）。
- 方法：多线程 + `http.client` 直连，不经过浏览器；所有数据都在本机，测的是
  **服务本身的并发与鉴权面**，不是家宽带宽（带宽见附录 B.8 / B.10）。

## 二、容量：瓶颈是长连接，不是 CPU

2000 次 `/api/system/ping`，32 并发线程：

| 场景 | p50 | p95 | 结果 |
| --- | --- | --- | --- |
| 无其他负载 | 30 ms | — | 2000 / 2000 |
| 另持 64 条 `/api/events`（SSE） | **242 ms** | 800+ ms | 2000 / 2000，整体发涩 |
| 修复后，持 32 条 SSE（上限内） | 16.9 ms | 34.2 ms | 1000 / 1000 |

**结论**：`/api/events` 每条连接都会永久占住一份并发配额（响应不结束），
而订阅者数量原本**没有上限** —— 任何持有令牌的客户端（自己手机切后台重连、
开一堆标签页、或脚本刷）都能把服务拖成一锅粥。

**修复（ISSUE-045）**：`MAX_SUBSCRIBERS = 32` + 开流之前判容量，超限 429
`E4006`（"同时在看的页面太多"）。实测并发 36 条 → 32 条 200 + 4 条 429，
腾出名额后立即恢复。

## 三、黑盒：未授权视角能拿到什么

| 探测 | 结果 | 判读 |
| --- | --- | --- |
| 无令牌 `/api/items` 等 | 401 `E2002` | 鉴权前置，未泄露存在性 |
| 无令牌 `/api/auth/me`、`/api/devices` | 401 `E2001` | 同上 |
| `/.git/config`、`/metrics`、随机路径 | 404 | 没有 SPA 兜底 200，扫描器拿不到假信号 |
| `TRACE` / `PUT` / `DELETE` 根路径 | 405 `Allow: GET, HEAD` | 方法白名单生效 |
| 伪造 `Authorization: Bearer xxx` | 401 | 签名校验前置 |
| 分片越界 | 413 `E1007`（不是 `E1006` 文件超限） | 错误码不再误导客户端 |
| 分片乱序 | 416 `E1011` | 会自愈重传 |
| `init` 里带 `target_rel=../escape` | 落盘位置不变 | 归档目录由 `upload.subdir` 决定，客户端字段只回显 |
| `/api/pair` 连错 20 次 | 429 `E4004` | 6 位码暴力破解不可行（6 位空间 + 5 次/码 + 20 次/10 分钟/IP） |
| 并发上传超限 | 429 `E4002` | 有并发闸门 |
| SSE 超限 | 429 `E4006` | 本轮新增 |
| 响应头 `Server` | 已移除 | 不再自报 `uvicorn` 指纹 |

## 四、仍然开放的

1. **明文 HTTP**：组网链路（Tailscale）本身是加密的，但从 Tailscale 出口到
   服务这一段是 `http://`。要真正对外，需要自有域名 + 证书（附录 B.10）。
2. **`target_rel` 是死字段**：安全（被忽略），但接口文档必须写明"仅回显"，
   否则后来者会以为它能指定目录。
3. **单机单进程**：电脑休眠/断电/关机即不可用；没有多副本或故障转移。
4. **不在本轮范围**：SQL 注入（全参数化，历史审计已核）、文件系统穿越
   （历史审计已核，`%2e%2e%2f` / UNC / ADS 全拒）。

## 五、复现命令

```powershell
# 容量的粗测（本机）
python build/_stress_sec.py            # 2000 次 ping + 并发变体
# 订阅上限（修复后应为 32×200 + 4×429）
python build/_stress_sec5.py
# 黑盒安全面
python build/_stress_sec2.py           # 未授权面
python build/_stress_sec6.py           # 上传/配对边界
```

## 六、给使用者的三句话

1. 现在的瓶颈是**长连接数量**，不是照片大小；手机端页面开太多会看到
   "同时在看的页面太多"，关掉几个标签页即可。
2. 这个服务只应暴露在**组网内网**（Tailscale/Radmin）；不要把 8799 直接映射到公网。
3. 令牌等于照片访问权：`build/_probe_token.txt` 这类文件用完即删，不要提交进仓库。
