# 安全审计与加固（2026-10-23）

> 范围：`cloud/relay`（公网中继）、家用 agent（`backend/app`）、前端（`frontend/src`）、
> 部署面（`cloud/deploy.ps1`、`scripts/cloud_init.py`、阿里云实例 `203.0.113.10`）。
> 触发器：用户提出「防止被人发现漏洞、攻击我的电脑」。
> 分支：`security/hardening-2026-10-23`（代码改动全部在此，`main` 未动）。

## 一句话结论

**功能面是干净的，暴露面不是。** 黑盒打了 60 多条请求、白盒读了三条链路的关键路径，
没有找到一条"不用密码就能进你家电脑"的路：路径穿越被 `sandbox.py` 挡死、配对码是
`secrets` 生成的 6 位一次性码、令牌是 HMAC-SHA256 签名且绑定设备、所有 SQL 都是参数化、
IDOR 全部按 `media.id` + `root_id` 二次校验。真正的问题集中在三个地方：

1. **伺服面**：公网入口前面没有任何安全响应头（CSP/XFO/Referrer-Policy 只写在一个没被部署的
   `cloud/Caddyfile` 里），且 **cloudflared 与端口转发都从 `127.0.0.1` 连入，中继把
   "127.0.0.1" 当成了真实客户端 IP** —— 于是全世界的访客共用一个限流桶，**任何人每分钟发
   10 个假密码就能把你自己锁在门外**（已实测复现）。
2. **密钥卫生**：服务器 `Administrator` 的口令明文躺在 `build/_askpass.cmd` 里，同期 **3389
   对全网开放**；一个 90 天有效的客户端令牌落在 `build/_sec_token.txt` 和一次端到端测试
   日志里；`cloud/deploy.ps1` 把 `PbCloud2026!` 写成 `-Password` 的默认值，而有一条测试
   断言"默认口令必须存在" —— **缺陷被测试钉成了契约**。
3. **单点拖死**：家用 agent 的 `/api/system/info` 每次请求都同步递归遍历一次缩略图缓存。
   照片多了以后**任何一个已配对的令牌**都能把事件循环占满，这是远程 DoS，不需要漏洞。

## 1. 方法与边界

- **黑盒**：从我这台机器（公网 IP `182.139.160.152`）经隧道与直连两种入口打请求，

  `frontend/src`、部署面与密钥；我自己复核了它们的每一处 `file:line`。
- **边界（重要）**：**没有做破坏性测试**。没有尝试真实的口令爆破、没有对生产实例

## 4. 确认没有问题的面（避免过度修复）

这些是白盒逐行看过、黑盒打过的，**不要再改**：

- **路径沙箱**（`backend/app/sandbox.py`）：`\`→`/` 归一 → 逐段检查 → `realpath` 求根 →
  逐段 `lstat` 查 reparse → `commonpath` 断言。`%2e%2e%2f`、`%5c`、`\\?\`、UNC、盘符、
  ADS、保留名、尾随点/空格、BIDI 全拒；junction 由 reparse 检查拦。**没找到穿越洞。**
- **上传目标路径**：`target_rel=..` 能通过 `init`（201），但落盘时被归一进
  `手机上传/<年>/<月>/`，**没有逃出根目录**（我实测过 3 种形态，`_probe9`）。
- **IDOR**：`raw`/`thumb`/`preview` 全按 `media.id` 取行、`root_id` 取自 DB；
  秒传 `find_duplicate` 带 `root_id` 过滤并二次 `stat`。
- **令牌**：HMAC-SHA256 签名、绑定 `device_id`（换设备 403 `E2003`）、篡改即 401。
  cookie 与 `Authorization` 两条路都验签。
- **配对码**：`secrets.randbelow(10**6)` 6 位、TTL 300 s、一次性（条件 `UPDATE` 抢占）、
  每码内存 5 次、按设备+IP 锁定、匿名入口有独立限流桶。
- **CSRF**：所有 `POST` 强制 `Content-Type: application/json`（`text/plain` 与
  `form-urlencoded` 直接拒）⇒ 跨站表单无法构成写入。
- **SQL**：全参数化。
- **CORS**：精确白名单、不发 `Allow-Credentials`。
- **`/agent/ws`**：无 token / 假 token / query 参数 token 全部 401。
- **XSS 面**：全仓零 `v-html`/`innerHTML`/`eval(`/`javascript:`/`<iframe`/`srcdoc`；
  文件名与 EXIF 全走 `{{ }}` 插值。
- **静态目录穿越**（云端页）：`realpath` + `commonpath` 挡死。

## 5. 残留风险（不改架构消不掉）

1. **明文 HTTP + 随机隧道域名**。`trycloudflare` 的域名每次重启都变，且**出口在美国洛杉矶**
   （`Registered tunnel connection … location=lax07`，RTT +1.4 s）。任何人只要知道当日域名就能
   访问你的配对页（配对仍需 6 位码，但"能不能看见页面"和"能不能进"是两件事）。
   **根因是"没有域名 + 没有 TLS 证书"**，不是代码。方向：买域名 + 一个正式的 Cloudflare
   Named Tunnel（或阿里云证书 + 反代）。
2. **实例带宽峰值 1 Mbps**（ISSUE-029）。这不是安全问题，但它是"为什么不买域名也能用"的
   另一面：现在的吞吐是穿透隧道的 135 KB/s 级别。
3. **服务器口令复用**（SEC-25/SEC-29）。我没改 —— 改了你会被自己的 VNC 控制台锁在外面。
   这是**必须由你决定**的一条。
4. **`/panel` 回环门依赖"来源 IP 不可伪造"**。SEC-01/SEC-02 修好后它是真的不可伪造了，
   但这套设计仍然是"网络位置即权限"，一旦将来再引入一层代理又要重算。
5. **HTTP 面无 Host 校验**（SEC-03）。现在靠"入口只有 cloudflared"兜着。
6. **`docs/11` 与 10-20 报告里引用了不存在的测试**：`cloud/tests/test_cloud_no_disk.py`、
   `cloud/tests/test_cloud_schema.py`、仓库根 `tests/` 都不存在。云端相关断言实际活在
   `backend/tests/test_cloud_deploy.py` 与 `test_p1_pages.py`。**这是审计里最该记住的一条**：
   文档里的"已验收"如果指不到可执行的判据，它就是叙事而不是证据。

## 8. 三条教训

1. **"能工作"和"能扛住别人用"是两套判据。** 1539 条测试全绿，其中 0 条断言过
   "响应里有 CSP"、"限流桶按真实客户端 IP 分"、"部署目录的 ACL 是什么"。缺陷不在被测
   的逻辑里，在**没人写判据的地方**。

   才没进 git —— **这是运气**。所以判据要落在 `test_secrets_hygiene.py` 里，而不是落在

**B1 · SEC-11 一个请求打满事件循环**

```powershell

  Invoke-RestMethod http://127.0.0.1:8787/api/system/info -Headers @{Authorization="Bearer <手机令牌>"} } }
```

**B2 · SEC-13 续写别人的上传会话**

```powershell
# 手机 A：init 一个 10 MB 文件，拿到 upload_id 后故意不传
# 手机 B（另一台设备、同一个文件同名同大小）：init → 修前返回 A 的 upload_id
```

**B4 · SEC-15 `Range: bytes=²-` → 500**

**B6 · SEC-12 解压炸弹**
