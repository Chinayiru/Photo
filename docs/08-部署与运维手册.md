### 1.2 三个部署单元

本项目由**三个单元**组成，它们各自的职责与部署位置完全不同：

| # | 部署单元 | 位置 | 跑什么 | 装什么 | 谁维护 |
|---|---|---|---|---|---|
| **①** | **云服务器** | 境外/香港 VPS（Linux） | Relay 服务 + Caddy（TLS 终止） | Docker + Docker Compose | 你（本手册 §2、§4） |
| **②** | **你的电脑** | 家里 Windows（数据在这里） | PhotoBridge Agent（托盘常驻） | 免安装 exe（PyInstaller onedir） | 你（本手册 §5） |
| **③** | **手机** | 任何网络 | Chrome / PWA（**无需安装**） | 什么都不装，浏览器打开网址 | 你（本手册 §6） |

> **关键认知**：**照片本体永远只在 ② 上**。① 只转发不存储；③ 只是个浏览器。
> 所以 ① 挂了、重装了、换服务商了，**你的照片一张都不会丢**（[设计文档.md](../设计文档.md) §2.1 决策②）。

**关键依赖关系**：

| 步骤 | 依赖什么 | 不做的后果 |
|---|---|---|
| 第 1 步（买 VPS） | 无 | 第 4 步无法进行 |
| 第 3 步（域名解析） | 已买域名 | 第 4 步 Caddy 无法签发证书（**Let's Encrypt 必须能通过 80 端口验证域名**） |
| 第 4 步（云端部署） | 第 1、2、3 步全部完成 | 第 5 步电脑端连不上云 |
| 第 5 步（电脑端） | 第 4 步完成 | 第 6 步手机端无法配对 |
| 第 6 步（手机端） | 第 5 步完成（电脑端要在线才能配对） | 无法使用 |

> **重要提醒**：**C1–C2 开发阶段完全不需要 VPS 和域名**。
> 那两步在本机（localhost）就能全部验证。VPS + 域名直到 **C3（手机联调）** 才真正需要（[设计文档.md](../设计文档.md) §10.1.2）。
> 所以**不要为了"先把环境搭好"而提前买**——等你确认架构成立（G2 检查点通过）再买。

## 2. 云服务器开通（从零开始）

### 2.1 选型建议

**结论先行**：买 **RackNerd 1GB 年付 $21.99（≈¥160/年 ≈ ¥13/月）**。
如果你想省心、不想折腾国际支付，就用 **阿里云/腾讯云香港轻量**（¥24–30/月）。

#### 2.1.1 三档方案对比

| | **① RackNerd**（推荐） | **② Oracle Cloud 免费** | **③ 阿里云/腾讯云香港** |
|---|---|---|---|
| 配置 | 1 vCPU / 1 GB / 20 GB SSD | ARM 4 核 / 24 GB / 200 GB | 1–2 核 / 1–2 GB |
| 带宽 | 1 Gbps 端口 / 3 TB 月流量 | 1 Gbps / 10 TB 月出站 | 峰值 30 Mbps / 1 TB 流量 |
| 价格 | **$21.99/年 ≈ ¥13/月** | **¥0（永久免费）** | ¥24–30/月 |
| 地区 | 洛杉矶 / 圣何塞 / 西雅图 / 达拉斯 | 日本大阪·东京、韩国首尔、新加坡 | **香港** |
| 大陆延迟 | 150–200 ms | 60–120 ms | **50–80 ms（最好）** |
| 备案 | **免备案** | **免备案** | **免备案** |
| 注册难度 | 低 | **高（信用卡验证常被拒）** | 低（中文控制台） |
| 主要风险 | 晚高峰国际线路可能绕路 | 容量紧张可能开不出机器；长期不活跃可能被回收 | 贵一倍 |
| 适合 | **想省心、马上能用** | 愿意折腾、追求零成本 | 追求最低延迟、不想折腾国际支付 |

> 完整分析见 [VPS选购建议.md](../VPS选购建议.md)。

#### 2.1.2 为什么最便宜的档位就够

这个项目对云服务器的要求**极低**——它只做转发，不跑数据库重活、不转码、不存文件：

| 资源 | 实际需求 | 说明 |
|---|---|---|
| CPU | 1 核足够 | 转发是 I/O 密集型，单用户场景下 CPU 常年 < 5% |
| 内存 | 512 MB–1 GB | Relay 常驻约 **80–150 MB**；但流控窗口 + 并发需要余量，1 GB 更稳 |
| 硬盘 | 20 GB 绰绰有余 | **云端零存储**，实际占用 < 500 MB（镜像 + `cloud.db`） |
| 流量 | 500 GB/月足够 | 按 [设计文档.md](../设计文档.md) §12 预算，实际约 **4.6 GB/月（用掉 0.15%）** |
| **带宽** | **≥ 5 Mbps** | ⚠️ **这是唯一真正影响体验的参数**：3 Mbps 下下载一张 4 MB 原图要 11 秒 |

> **选型三条硬指标**（按重要性排序）：
> 1. **带宽 ≥ 5 Mbps** —— 唯一真正影响体验的参数
> 2. **地区** —— 优先香港/境外（免备案）
> 3. **流量 ≥ 500 GB/月** —— 正常使用约 4.6 GB/月，几乎不可能超

> **省钱的真正关键**：不要在 VPS 上多花钱。你的钱应该花在——
> ① 保证家里**宽带上传速度**；② 让"手机在家走局域网直连"这个功能做好（C5 阶段）。
> 后者比任何 VPS 升级都快（千兆内网 ≈ 1000 Mbps）。

### 2.3 首次登录前的准备（在你的 Windows 电脑上）

#### 2.3.1 检查是否有 ssh 命令

Windows 10 1809+ 和 Windows 11 **自带 OpenSSH 客户端**。打开 PowerShell：

```powershell
ssh -V
```

**预期输出**（版本号可能不同）：

```
OpenSSH_for_Windows_9.5p1, LibreSSL 3.8.2
```

| 结果 | 怎么办 |
|---|---|
| 显示了版本号 | ✅ 继续 §2.4 |
| `ssh : 无法将"ssh"项识别为 cmdlet...` | 用 **PuTTY**（§2.3.2），或安装 OpenSSH：`设置 → 系统 → 可选功能 → 添加可选功能 → OpenSSH 客户端` |

#### 2.3.2 备选：用 PuTTY

如果不想用命令行：

```
1. 下载 PuTTY：https://www.putty.org/
2. 打开 PuTTY
3. Host Name (or IP address): 填 VPS 的 IP
4. Port: 22
5. Connection type: SSH
6. 点 Open
7. 首次连接会提示 "The server's host key is not cached..." → 点 Accept
8. login as: root
9. password: 粘贴 VPS 密码（★ 粘贴时屏幕上不显示任何字符，这是正常的）
```

> **注意**：PuTTY 里粘贴用**鼠标右键**（不是 Ctrl+V）。

#### 2.3.3 生成 SSH 密钥（推荐，本手册主推方式）

**在你自己的 Windows 电脑上**执行（不是服务器上）：

```powershell
ssh-keygen -t ed25519 -C "photobridge-vps"
```

交互过程：

```
Generating public/private ed25519 key pair.
Enter file in which to save the key (C:\Users\alice/.ssh/id_ed25519):   ← 直接回车
Enter passphrase (empty for no passphrase):                              ← 建议设一个密码
Enter same passphrase again:                                             ← 再输一遍
```

**产出**：

| 文件 | 说明 | 能不能给别人 |
|---|---|---|
| `C:\Users\alice\.ssh\id_ed25519` | **私钥** | ❌ **绝对不能**，这是你的身份 |
| `C:\Users\alice\.ssh\id_ed25519.pub` | **公钥** | ✅ 可以，就是要放到服务器上的 |

> **注意**：上面路径里的 `18240` 是你的 Windows 用户名。用 `echo $env:USERPROFILE` 确认自己的实际路径。

### 2.4 首次登录服务器

#### 2.4.1 用密码登录（第一次）

```powershell
ssh root@198.51.100.42
```

> 把 `198.51.100.42` 换成你的 VPS 实际 IP。

**首次连接会提示**：

```
The authenticity of host '198.51.100.42 (198.51.100.42)' can't be established.
ED25519 key fingerprint is SHA256:xxxxxxxxxxxxxxxxxxxxxxxxxxx.
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

输入 `yes` 回车。

然后输入 `root` 的密码（**粘贴时屏幕上不显示任何字符**，这是正常的，直接回车）。

**登录成功后**，你会看到类似提示符：

```
root@racknerd-xxxxxxxx:~#
```

#### 2.4.2 确认你连对了机器

```bash
# 看系统版本（应该是 Ubuntu 24.04）
lsb_release -a

# 看内存（应该是 1 GB 左右）
free -h

# 看磁盘（应该是 20 GB 左右）
df -h /

# 看 CPU 核数
nproc
```

**预期输出示例**：

```
Distributor ID: Ubuntu
Description:    Ubuntu 24.04.1 LTS
Release:        24.04
Codename:       noble
```

> 如果 `lsb_release` 提示找不到命令，先执行 `apt update && apt install -y lsb-release`。

### 2.5 系统更新

**第一步永远是更新系统**：

```bash
apt update && apt upgrade -y
```

如果提示有内核更新或 `*** System restart required ***`：

```bash
# 重启（会断开 SSH 连接，等 30 秒再重连）
reboot
```

重启后重新登录（`ssh root@你的IP`）。

**安装常用工具**：

```bash
apt install -y curl wget git vim htop ufw fail2ban unzip ca-certificates gnupg lsb-release
```

| 工具 | 用途 |
|---|---|
| `curl` / `wget` | 下载安装脚本 |
| `git` | 拉取部署文件（可选） |
| `vim` | 编辑配置文件 |
| `htop` | 看 CPU/内存实时占用（§9） |
| `ufw` | 防火墙（§2.8） |
| `fail2ban` | 防 SSH 爆破（§2.9） |
| `ca-certificates` | HTTPS 证书根（Docker 安装需要） |

### 2.6 创建非 root 用户

**永远不要用 root 日常操作**。创建一个普通用户，之后都用它登录。

```bash
# 1. 创建用户（把 deploy 换成你想要的名字，本手册统一用 deploy）
adduser deploy
```

交互过程：

```
New password:                    ← 设一个强密码（会和 SSH 密钥并存，作为备用）
Retype new password:             ← 再输一遍
Full Name []:                    ← 直接回车
```

### 2.7 SSH 密钥登录 + 禁用密码登录

#### 2.7.1 把公钥放到服务器上

**方法 A：用 ssh-copy-id（最简单，如果你在 Windows 上有 bash/WSL/Git Bash）**

```bash
ssh-copy-id deploy@198.51.100.42
```

**方法 B：用 PowerShell 手动复制（Windows 原生推荐）**

在**你自己的 Windows 电脑**上执行：

```powershell
# 读取公钥内容
$pubkey = Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
# 把公钥追加到服务器的 authorized_keys
ssh deploy@198.51.100.42 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$pubkey' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

执行时会让你输入 `deploy` 用户的密码（刚才设的那个）。

**验证公钥已就位**：

```powershell
ssh deploy@198.51.100.42 "cat ~/.ssh/authorized_keys"
```

应该输出一行 `ssh-ed25519 AAAA... photobridge-vps`。

#### 2.7.2 验证密钥登录能用（★ 关键步骤，别跳过）

**先不要关闭当前 root 会话**，另开一个 PowerShell 窗口：

```powershell
ssh deploy@198.51.100.42
```

| 结果 | 说明 |
|---|---|
| ✅ 直接登录，**没让你输密码** | 密钥生效，继续 §2.7.3 |
| ❌ 还是让你输密码 | 密钥没生效，**不要继续**！回到 §2.7.1 检查 |

> ⚠️ **这一步必须验证通过才能禁用密码登录**。否则你会把自己锁在服务器外面，
> 只能通过服务商控制面板的 VNC/救援模式进去改，非常麻烦。

#### 2.7.3 禁用密码登录

在服务器上（用 `deploy` 用户登录后）：

```bash
sudo tee /etc/ssh/sshd_config.d/99-hardening.conf > /dev/null <<'EOF'
# PhotoBridge SSH 加固
PasswordAuthentication no
PubkeyAuthentication yes
PermitRootLogin no
ChallengeResponseAuthentication no
KbdInteractiveAuthentication no
UsePAM yes
EOF

# 校验配置语法（★ 必须先校验，防止写错导致 sshd 起不来）
sudo sshd -t
```

| `sshd -t` 结果 | 动作 |
|---|---|
| 无输出 | ✅ 配置合法，继续 |
| 有 `error` 输出 | ❌ **不要重启 sshd**，先修配置 |

```bash
# 重启 SSH 服务
sudo systemctl restart ssh

# 确认服务在跑
sudo systemctl status ssh --no-pager
```

**★ 验证（同样保持当前会话不要关）**，另开窗口：

```powershell
# 用密钥应该能登录
ssh deploy@198.51.100.42 "echo OK"

# 用密码应该被拒绝（这一步会失败，这是预期的）
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password deploy@198.51.100.42
```

第二条命令**应该报错** `Permission denied (publickey).` —— 这说明密码登录已被禁用，加固成功。

> **如果密钥登录失败了**：别关当前会话！先 `sudo rm /etc/ssh/sshd_config.d/99-hardening.conf && sudo systemctl restart ssh` 恢复。

#### 2.7.4 顺便禁止 root 直接登录

上面的配置里已经有 `PermitRootLogin no`，root 无法直接 SSH 登录了。需要管理员权限时用 `sudo`：

```bash
sudo -i        # 切到 root（需要 deploy 的密码）
exit           # 退回 deploy
```

### 2.8 配置防火墙（ufw）

#### 2.8.1 只开三个端口

```bash
# 1. 设置默认策略：拒绝所有入站，允许所有出站
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 2. 放行 SSH（★ 必须先放行，否则会把自己锁在外面）
sudo ufw allow 22/tcp comment 'SSH'

# 3. 放行 HTTP（Caddy 用，也是 Let's Encrypt 域名验证必需）
sudo ufw allow 80/tcp comment 'HTTP - Caddy / Let''s Encrypt'

# 4. 放行 HTTPS
sudo ufw allow 443/tcp comment 'HTTPS - Caddy'
sudo ufw allow 443/udp comment 'HTTPS/3 QUIC'

# 5. 确认规则正确（此时还没启用）
sudo ufw show added

# 6. 启用防火墙（会提示确认，输入 y）
sudo ufw enable

# 7. 查看状态
sudo ufw status verbose
```

**预期输出**：

```
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp                     ALLOW IN    Anywhere                   # SSH
80/tcp                     ALLOW IN    Anywhere                   # HTTP - Caddy
443/tcp                    ALLOW IN    Anywhere                   # HTTPS - Caddy
443/udp                    ALLOW IN    Anywhere                   # HTTPS/3 QUIC
```

#### 2.8.2 ★ 重要：ufw 与 Docker 的坑

**这是最容易踩的坑之一**：Docker 会直接写 `iptables` 规则，**绕过 ufw**。
所以如果 `docker-compose.yml` 里把 relay 的 `8000` 端口发布到宿主机（`ports: ["8000:8000"]`），
那么 **8000 端口会绕过 ufw 暴露到公网**，即使 ufw 没放行。

**正确做法**（本手册的 `docker-compose.yml` 已经这么做）：

```yaml
# ✅ 正确：只在 Docker 内部网络暴露，不发布到宿主机
expose:
  - "8000"

# ❌ 错误：这样会绕过 ufw，8000 暴露到公网
# ports:
#   - "8000:8000"
```

只有 Caddy 需要发布端口（80/443），因为它就是要对外服务的。

**验证 8000 没有暴露**（在服务器上执行）：

```bash
# 从外部视角看端口（应该连不上 8000）
curl -m 3 http://198.51.100.42:8000/ ; echo "exit=$?"
```

| 结果 | 说明 |
|---|---|
| `exit=28`（超时）或 `Connection refused` | ✅ 正确，8000 未暴露 |
| 返回了 HTTP 响应 | ❌ 8000 暴露了！检查 compose 里是不是写了 `ports: ["8000:8000"]` |

### 2.9 安装 fail2ban

fail2ban 监控日志，发现多次登录失败就临时封禁该 IP，防 SSH 爆破。

```bash
# 1. 创建配置（在 Ubuntu 24.04 上 fail2ban 默认没有 jail.local）
sudo tee /etc/fail2ban/jail.local > /dev/null <<'EOF'
[DEFAULT]
# 封禁时长：1 小时
bantime  = 1h
# 检测窗口：10 分钟
findtime = 10m
# 10 分钟内失败 5 次就封
maxretry = 5
# 封禁整个 IP（默认就是）
banaction = ufw

[sshd]
enabled  = true
port     = 22
logpath  = %(sshd_log)s
backend  = %(sshd_backend)s
maxretry = 5
EOF

# 2. 启动并设为开机自启
sudo systemctl enable --now fail2ban

# 3. 确认状态
sudo systemctl status fail2ban --no-pager

# 4. 查看 sshd jail 的状态
sudo fail2ban-client status sshd
```

**预期输出**：

```
Status for the jail: sshd
|- Filter
|  |- Currently failed: 0
|  |- Total failed:     0
|  `- File list:        /var/log/auth.log
`- Actions
   |- Currently banned: 0
   |- Total banned:     0
   `- Banned IP list:
```

**常用命令**：

```bash
# 手动解封一个 IP（如果误封了自己）
```

#### 3.1.1 在哪买、买什么

#### 3.1.2 买域名的三个注意点

| # | 注意点 | 说明 |
|---|---|---|
| 1 | **看清续费价** | "首年 ¥1、续费 ¥30"是常见套路。**对你无所谓**——续费也就 ¥30/年 |
| 2 | **需要实名认证** | 国内注册商要求实名，通常 1–3 天审核。**买完马上去认证**，否则域名会被暂停解析 |

> 这三点价值远超十块钱。
>
> **没有域名会怎样**：只能用 `https://IP:8443` + 自签证书，手机要装根证书，很麻烦——**不推荐**。

#### 3.1.3 不用域名的两条备选（都不推荐）

|---|---|---|

| `nip.io` 通配解析 | `198.51.100.42.nip.io` 自动解析到该 IP | **无法申请 Let's Encrypt 证书**（不受控域名） |

### 3.2 DNS 解析：A 记录指向 VPS IP

#### 3.2.1 配置示例

登录你的域名注册商控制台，找到 **DNS 解析 / 域名解析** 页面，添加一条记录：

| 字段 | 填什么 | 说明 |
|---|---|---|
| **记录类型** | `A` | A 记录 = 域名 → IPv4 地址 |
| **主机记录** | `@` | `@` 表示域名本身（即 `photos.example.com`） |
| **解析线路** | 默认 | 有"境外"选项就选境外（VPS 在国外） |
| **记录值** | `198.51.100.42` | ★ 换成你的 VPS 实际 IP |
| **TTL** | `600`（10 分钟） | 首次配置用短 TTL，方便改；稳定后可改 3600 |

**如果你想要 `photos.example.com` 而不是 `example.com`**：

| 字段 | 填什么 |
|---|---|
| 主机记录 | `photos` |
| 记录值 | `198.51.100.42` |

**配置完的样子（示例）**：

```
主机记录    记录类型    解析线路    记录值            TTL
@          A          默认       198.51.100.42    600
```

#### 3.2.2 ★ 一定要确认的：域名是否被墙/污染

在服务器上或者本地执行：

```bash
# 看域名解析到哪个 IP
nslookup photos.example.com
```

如果解析结果**不是**你的 VPS IP，说明 DNS 还没生效或被劫持。

### 3.3 验证解析生效

#### 3.3.1 用 dig（Linux/macOS，或 Windows 装了 dig）

```bash
# 查 A 记录（最简）
dig +short photos.example.com

# 预期输出（应该就是你的 VPS IP）
198.51.100.42

# 查完整信息（含 TTL、权威服务器）
dig photos.example.com A
```

**预期输出片段**：

```
;; QUESTION SECTION:
;photos.example.com.		IN	A

;; ANSWER SECTION:
photos.example.com.	600	IN	A	198.51.100.42
```

#### 3.3.2 用 nslookup（Windows 自带）

```powershell
nslookup photos.example.com
```

**预期输出**：

```
服务器:  UnKnown
Address:  192.168.0.1

非权威应答:
名称:    photos.example.com
Address:  198.51.100.42
```

#### 3.3.3 用多个公共 DNS 交叉验证

DNS 缓存和不同 DNS 服务器可能导致结果不一致。用**多个公共 DNS** 验证：

```powershell
# Google DNS
nslookup photos.example.com 8.8.8.8

# Cloudflare DNS
nslookup photos.example.com 1.1.1.1

# 阿里 DNS
nslookup photos.example.com 223.5.5.5

# 腾讯 DNS
nslookup photos.example.com 119.29.29.29
```

| 结果 | 说明 |
|---|---|
| 四个都返回你的 VPS IP | ✅ 解析已全球生效 |
| 有的返回旧 IP / NXDOMAIN | ⏳ 还没生效，继续等 |
| 返回了**不是你设的** IP | ⚠️ 可能被劫持或配错了记录 |

#### 3.3.4 在线工具（最直观）

如果命令行结果让你困惑，用在线工具看全球生效情况：

- `https://dnschecker.org/` —— 输入域名，看全球各地 DNS 解析结果
- `https://www.whatsmydns.net/` —— 同上，地图展示

### 3.4 ★ 注意：DNS 生效需要时间

#### 3.4.1 为什么要等

DNS 是**分级缓存**的：你的电脑 → 路由器 → 运营商 DNS → 根/权威服务器。
每一级都有自己的 TTL 缓存。**你改了记录，但别人的缓存还没过期**。

#### 3.4.2 时间预期

| 场景 | 生效时间 |
|---|---|
| 全新添加记录（之前没有） | **通常 1–10 分钟**，最快几十秒 |
| 修改已有记录的 IP | 取决于旧记录的 TTL，**最长可能几小时** |
| TTL 设为 600（10 分钟） | 最坏情况 10 分钟后全球生效 |
| 国内注册商 + 实名认证未完成 | **可能一直不生效**（域名被暂停解析） |

#### 3.4.3 怎么确认生效

**判断标准**：用 §3.3.3 的四个公共 DNS 查询，**全部**返回你的 VPS IP，就算生效了。

**在服务器上验证（最直接，因为 Let's Encrypt 也是这么看的）**：

```bash
# 在 VPS 上执行
dig +short photos.example.com @8.8.8.8
```

如果返回你的 VPS IP，说明**从公网视角**已经解析正确。

#### 3.4.4 加速生效的土办法

| 方法 | 说明 |
|---|---|
| 把 TTL 先设短（如 60） | 改记录时更快生效；稳定后再调长 |
| 刷新本地 DNS 缓存 | Windows：`ipconfig /flushdns`；Linux：`sudo systemd-resolve --flush-caches` |
| 用 `--resolve` 绕过本地 DNS 测试 | `curl --resolve photos.example.com:443:198.51.100.42 https://photos.example.com/` |

#### 3.4.5 ★ 不要跳过这一步

**在 DNS 生效之前，不要去 §4 部署 Caddy**。

原因：Caddy 启动时会立即尝试为你的域名申请 Let's Encrypt 证书。
如果此时域名还没解析到这台机器，**验证会失败**，而且 **Let's Encrypt 有速率限制**
（同一域名每周 5 次失败就会锁定），反复失败会让你等一周（见 §10 场景 5）。

**正确的顺序**：

```
买域名 → 配置 A 记录 → 等待生效（dig 验证通过） → 部署 Caddy
```

| # | 检查项 | 验证命令 | 预期 |
|---|---|---|---|
| 1 | 域名已购买且实名认证通过 | 注册商控制台 | 状态正常，未被暂停 |

| 3 | 解析已生效（多 DNS 验证） | `nslookup 域名 8.8.8.8` 等四个 | 全部返回 VPS IP |
